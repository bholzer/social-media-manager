  <action>
Make two changes to `src/smm/api/v1/oauth.py`:

1. **`GET /facebook/connect`** — Change from returning `RedirectResponse(url=url)` to returning `{"url": url}` as JSON. The frontend needs to call this with a Bearer token via `api.get()`, get the Facebook authorization URL back, then navigate the browser to it. A 302 redirect cannot carry the Authorization header from the browser. Keep the `get_current_user` dependency as-is.

2. **`GET /facebook/callback`** — Change the two return paths to redirect to frontend routes instead of returning JSON:
   - **When pages exist:** Build a frontend URL `/accounts/facebook/callback` with query params `pages` (URL-encoded JSON array of `{page_id, name}` objects) and `token` (the `long_tokens.access_token`). Return `RedirectResponse(url=frontend_url)`. Use `urllib.parse.quote` for encoding.
   - **When no pages (profile connected):** Return `RedirectResponse(url="/accounts?connected=true")`.
   - **On errors:** For the existing `HTTPException` cases, instead change them to redirect to `/accounts?error=<url-encoded message>`. Replace the three `raise HTTPException` blocks in the callback function body (after state validation and during token exchange/page fetch) with `RedirectResponse(url=f"/accounts?error={quote(message)}")`. Keep the state validation errors (invalid/expired state) as HTTPExceptions since those indicate tampering.

Add `from urllib.parse import quote` at the top. Also add `import json` if not already present (for `json.dumps` of pages list).
  </action>

**A. Create `src/client/src/pages/FacebookOAuthCallbackPage.tsx`:**

This page handles the return from Facebook OAuth after the backend callback redirects here.

Component behavior:
- Read query params using `useSearchParams` from `react-router`: `pages`, `token`, `error`
- **If `error` param exists:** Show error message with a link back to `/accounts`
- **If `pages` param exists:** Parse it (`JSON.parse(decodeURIComponent(pages))`), display a list of Facebook Pages as clickable cards/buttons. Each shows the page `name`. When user clicks a page, call `api.post('/oauth/facebook/connect-page', { page_id, page_name: name, oauth_user_token: token })`. On success, navigate to `/accounts?connected=true`. On failure, show error inline.
- **If neither `pages` nor `error`:** Show a "Redirecting..." message and navigate to `/accounts` (fallback for unexpected states)
- Show a loading spinner/state while the connect-page POST is in flight
- Style with Tailwind consistent with existing pages (white card with shadow, centered content)

**B. Update `src/client/src/router.tsx`:**

Add import for `FacebookOAuthCallbackPage`. Add a route inside the protected `AppLayout` children array:
```
{ path: 'accounts/facebook/callback', element: <FacebookOAuthCallbackPage /> }
```
Place it after the `accounts` route.

**C. Update `src/client/src/pages/AccountsPage.tsx`:**

1. Add a "Connect Facebook" button. Place it between the heading section and the accounts list. Style as a primary button (blue bg, white text, rounded, Tailwind classes matching project style).

2. Button click handler `handleConnectFacebook`:
   - Set a loading state to disable the button
   - Call `api.get<{ url: string }>('/oauth/facebook/connect')`
   - On success, do `window.location.href = data.url` to navigate to Facebook
   - On error, show error message in the `error` state

3. Read `?connected=true` query param on mount (via `useSearchParams`). If present, show a success banner/toast at the top ("Facebook account connected successfully!") and re-fetch the accounts list. Clear the param from the URL using `setSearchParams` or `navigate('/accounts', { replace: true })` after showing the message.

4. Read `?error=` query param on mount. If present, show the error message in a red banner.
